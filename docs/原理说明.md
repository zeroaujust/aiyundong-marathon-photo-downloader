# 原理说明

本文档完整记录对爱云动（runnerbar）平台接口的逆向过程与关键发现，供想深入理解或扩展到其他平台的读者参考。

> 所有接口都是通过分析平台 H5 站（`m.yundong.runnerbar.com`）的前端 JS（`app.js` 及各 chunk）还原的，前端怎么写，我们就怎么发请求。

## 1. 平台架构

```
微信小程序「爱云动」 ┐
H5 站 m.yundong.runnerbar.com ┼→ https://apiface.store.runnerbar.com （生产 API）
                    ┘   （测试环境 api.corp.yundongpai.net 返回内部测试数据，勿用）
                              │
                              ├→ 业务 API（JSON）
                              └→ 阿里云 OSS（图片直传/下载，oss.runnerbar.com）
```

关键事实：
- 所有业务接口都是 **POST + query string 参数 + 空 body**（前端用 axios 的 `params`）
- 响应是明文 JSON（无需解密）
- 图片下载域名 `oss.runnerbar.com`，水印版路径形如 `/img/watermark/user_upload/origin/<日期>/<id>_<uuid>.jpg`

## 2. 接口清单

### 2.1 赛事列表（发现赛事）

```
GET/POST /yundong/yd_portal/getPortalActivityV3.json?index=0&size=100
```

- 分页拉取门户赛事，每页 100 条，按发布时间排序
- 响应 `result.portalList[]`，关键字段：`id`（赛事 ID）、`title`（赛事名）、`start_time`（毫秒时间戳）、`activity_photo_count`（照片总数）、`is_faceSearch`（是否开人脸搜索）
- 匹配策略：把用户关键词按非中英数字切词元，**所有词元都要出现在赛事名里**；年份优先匹配标题中的 `20\d{2}`，其次用 `start_time` 的年份

### 2.2 参赛号搜索（核心）

```
POST /yundong/faceSearch/getFaceAndGameNumSearchPhotoV2.json
    ?uid=0&activity_id=36231&game_number=B10426&photoNum=200&source=h5
```

- `game_number` 支持模糊：`B10426` 精确、`10426` 匹配所有号码段、`B1042` 前缀匹配（会返回几百张别人的，别用）
- 大小写不敏感（`b10426` 等价 `B10426`）
- 响应 `result.topicInfoList[]`：
  - `media_show_type == 1` 是真实照片，`== 2` 是广告占位（要剔除）
  - `url` / `url_hq` / `url_lq` 分别是标准/高清/低清水印版 URL
  - `is_canbuy` / `standard_price`：原图付费信息
  - `result.count`：平台原始计数（含广告位）；`result.video`：赛事视频数（0 即无视频）
  - `result.newTopicInfoList`：增量照片（一般空）
- **`uid=0` 即可匿名搜索**，不需要登录

### 2.3 图片上传（人脸搜索的前置步骤）

复刻前端 `UploadAli` 流程，两步：

**第一步：取 OSS 上传凭证**

```
POST /yundong/yd/upload/generalOssRequestMap.json
    ?function=faceSearch&timestamp=<毫秒>&sign=<签名>&md5=<文件md5>&uid=0
```

签名算法（前端 `app.js` 里写死）：

```python
sign = MD5("function=faceSearch&md5=" + 文件MD5 + "&timestamp=" + 毫秒时间戳 + "&uid=" + uid + "&secret=iyd")
```

⚠️ **最大的坑：`uid` 传空字符串会被服务端拒绝，返回 `-100 sign错误`。必须传非空值（如 `"0"`）。** 前端代码里是 `uid = cookie里的ayduid || ""`，未登录用户也会命中这个坑——但服务端实际校验要求 uid 非空，这是前端与服务端行为不一致的地方。

响应 `result.respMap`：`accessid` / `policy` / `callback` / `signature` / `host` / `dir`。

**第二步：直传阿里云 OSS**

```
POST <respMap.host>   （multipart/form-data）
字段：OSSAccessKeyId, policy, callback, Signature, key, success_action_status=200, md5, file
```

`key` 格式必须与前端一致，否则 callback 校验失败：

```
key = dir + timestamp + "-" + uuid4(带横杠) + 文件字节数 + ".jpg"
```

成功响应 `{"Status":"OK"}`。

### 2.4 人脸检测

```
POST /yundong/faceSearch/saveSearchFaces.json?uid=0&activity_id=36231&face_url=<oss key>
```

- `face_url` 是第一步上传返回的 OSS key（**不是完整 URL**，不能带 `https://oss.runnerbar.com/` 前缀）
- 响应 `list[]`：照片里检测到的每个人脸 `{id, url}`——`id` 即 face_id，`url` 是平台裁好的人脸小图
- 一张照片可能检出多个人脸（本人 + 同框的其他跑者 + 路人）

### 2.5 人脸搜索

```
POST /yundong/faceSearch/getFaceAndGameNumSearchPhotoV2.json
    ?uid=0&activity_id=36231&face_id=<face_id>&photoNum=200&source=h5
```

- 响应结构同 2.2，返回该人脸在赛事全部照片里的匹配结果
- 注意 V2 的 `url` 参数会被忽略（只认 `face_id` 或 `game_number`）；旧版 V1 接口 `getFaceAndGameNumSearchPhoto.json` 只认人脸 url、不认纯参赛号

## 3. 「92 缺口」问题：为什么号码搜索只有一半照片

实测案例（2026 西青区半程马拉松，参赛号 B10426）：

| 方式 | 数量 |
|---|---|
| 小程序显示 | 92 |
| 参赛号搜索（V2） | 47 |
| 人脸搜索并集（43 个本人人脸） | 145 |

**结论：小程序把「号码搜索 + 人脸匹配」合并展示。** 平台收录的照片里，大量照片只打了人脸标签没打号码（或号码被遮挡/拍不到），纯号码搜索天然漏一半。

## 4. 收敛过滤：如何从 145 里剔出误匹配

人脸搜索的并集（145）大于真实数量（92），因为每个角度的「本人脸」搜索结果里都混有**相貌相近的其他跑者**。

关键观察（43 个本人人脸的统计）：

- 本人脸的搜索结果与号码结果（47 张）的重合数：**26 ~ 46**
- 其他跑者脸的重合数：**≤ 7**（他们的结果数高达 100+，但几乎不碰你的号码照片）

两个过滤条件：

1. **归属判定**（`overlap >= 15`，默认）：人脸搜索结果与号码结果重合数达标 → 认定是本人脸
2. **收敛确认**（`min_faces >= 2`，默认）：最终照片必须被 **≥2 个不同角度的本人人脸**同时找到

按此过滤后：**恰好得到 92 张**——与小程序显示数完全一致。被单个人脸找到的 52 张基本都是误匹配（其他跑者），已剔除。

> 直觉解释：真正的你，从任何角度拍都认得出；误匹配的跑者，只有一个角度像你。

## 5. 已知平台侧限制

- **视频搜索**：`/yundong/video/getFaceSearchPhoto.json` 对部分赛事返回 `-10000 服务器暂停服务`；专辑信息里 `video: 0` 的赛事则根本没有视频。按参赛号搜视频的接口不存在（探测过多个路径均 404）
- **原图**：水印版免费；去 URL 里的 `/img/watermark/` 前缀访问原图会 404，必须付费购买
- **赛事列表**：门户接口只返回最近若干页（每页 100），太老的赛事要翻更深的分页

## 6. 代码结构

```
aiyundong_downloader.py
├── http_request()          带重试的 HTTP
├── api_post()              平台 API 调用（query 参数 + POST 空 body）
├── class AiyunDong
│   ├── list_events()       拉赛事列表
│   ├── match_events()      关键词+年份匹配
│   ├── search_by_bib()     参赛号搜索
│   ├── upload_image()      OSS 两步上传（含签名）
│   ├── detect_faces()      人脸检测
│   └── search_by_face()    人脸搜索
├── download_one()          单张下载（重试+大小校验）
├── verify_image()          JPEG 校验（Pillow 可选）
├── make_contact_sheet()    缩略图总览
└── run()                   主编排：发现→搜索→人脸→收敛→下载→校验→总览
```

## 7. 扩展到其他平台

同样的方法适用于任何「小程序 + H5 + OSS 直传」架构的照片平台：

1. 浏览器打开 H5 站，F12 看 Network，找到搜索接口
2. 下载前端 JS，搜接口路径常量（如 `kapi_xxx`）定位调用代码
3. 复刻签名算法（找 `MD5(` / `secret` 等关键字）
4. 注意 query 参数 vs body、时间戳单位、uid 非空这类服务端隐性校验
